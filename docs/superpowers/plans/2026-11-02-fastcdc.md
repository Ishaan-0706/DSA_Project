## Global Constraints

- Public building block is the chunker. Do not add `rolling_hash.hpp`, a gear-hash header, or any other public hash type.
- Gear hash: `h = (h << 1) + table[byte]`, wrapping `uint64_t`. Update `h` on every byte, including bytes before `min_size`.
- Gear table: 256 `uint64_t` values from splitmix64, seed `0x424C4F434B444544`. Start from the seed. For each entry: `state += 0x9E3779B97F4A7C15`; `z = state`; `z = (z ^ (z >> 30)) * 0xBF58476D1CE4E5B9`; `z = (z ^ (z >> 27)) * 0x94D049BB133111EB`; `z ^= z >> 31`; store `z`. All arithmetic wraps `uint64_t`. Build the table once inside `fastcdc.cpp`.
- Normalization level 2. `bits = log2(avg_size)`. `mask_s = (1 << (bits + 1)) - 1`, used while `min_size <= n < avg_size`. `mask_l = (1 << (bits - 1)) - 1`, used while `avg_size <= n < max_size`. Cut when `(h & mask) == 0`. Force a cut at `n == max_size`. Never cut before `min_size`. The final chunk may be shorter than `min_size`.
- `min_size`, `avg_size`, and `max_size` are powers of two, `min_size >= 64`, and `min_size < avg_size < max_size`. That is a precondition. Say so on `FastCdcConfig`. No error channel.
- Defaults: `min_size = 2048`, `avg_size = 8192`, `max_size = 32768`.
- Do not add a library for hashing or chunking.
- Do not change image-pipeline behavior. Renaming its test file is the only edit outside chunking.
- Run tests with `cmake -S . -B build && cmake --build build && ctest --test-dir build --output-on-failure`. `tests/build.sh` configures `-DBUILD_TESTING=OFF` and does not run this suite.

## Review Focus

- A config that breaks the power-of-two precondition is a caller bug. The header states that. There is no test and no recovery path.
- Identical bytes must produce identical cuts. The gear table is a compile-time function of the seed above. A second translation unit must not rebuild a different table.
- The hash is not a sliding window of fixed width. Bytes older than 64 steps fall off by the left shift. Cut positions can still stay apart after that, because each chunker's size counter depends on its previous cut. The edit test allows resync up to `max_size` bytes after the edit, which holds for the pinned buffers below.
- The last chunk is the only chunk allowed to be shorter than `min_size`, and it is also allowed to be shorter than 1 only when the input is empty.
- `tests/build.sh` will keep reporting success while this suite is broken, because it turns testing off.

**Interfaces:**
- Consumes: nothing from Task 1 except the library target
- Produces:

```cpp
namespace blockdedup::chunking {

struct Chunk {
    size_t offset;
    size_t size;
};

struct FastCdcConfig {
    // Powers of two, min_size >= 64, min_size < avg_size < max_size.
    size_t min_size = 2048;
    size_t avg_size = 8192;
    size_t max_size = 32768;
};

std::vector<Chunk> FastCdc(std::span<const uint8_t> data,
                           const FastCdcConfig& config = {});

}
```

`Chunk` offsets are ascending, contiguous, and start at 0. The sizes sum to `data.size()`.

- [ ] **Step 1: Write the failing test**

Create `tests/test_fastcdc.cpp` with the helper and cases below. `Fill` is splitmix64 from `seed`, one byte per step, top byte of `z` (`z >> 56`). Use the same splitmix steps as the gear table, starting from `seed` rather than from `0x424C4F434B444544`.

```cpp
static std::vector<uint8_t> Fill(size_t n, uint64_t seed);

static std::vector<uint8_t> Join(std::span<const uint8_t> data,
                                 const std::vector<blockdedup::chunking::Chunk>& chunks);
```

`Join` concatenates `data[c.offset .. c.offset + c.size)` and the tests `REQUIRE` it equals `data`.

Cases:

1. `FastCdc({})` is empty.
2. `FastCdc` of three bytes `{1, 2, 3}` with `{64, 256, 1024}` returns one chunk `{0, 3}`.
3. `Fill(306, 1)` with `{64, 128, 256}` returns chunks of size `256` then `50`.
4. `Fill(100000, 1)` with the default config: every chunk except the last has `size` in `[2048, 32768]`, the last has `size` in `[1, 32768]`, and `Join` round-trips.
5. Locality. `data = Fill(48 * 1024, 1)`, config `{64, 256, 1024}`. For each edit offset in `{0, 100, 16384, data.size() - 1}`, flip that byte with `^= 0xA5` and chunk both buffers.
   - Every chunk whose `offset + size <= edit` has the same `offset` and `size` in both results. For offset `16384` this prefix is non-empty: `REQUIRE` at least one such chunk.
   - Both results `Join` back to their buffer.
   - Let end offsets be `offset + size`. Find the first end `e > edit` that is in both sets and whose tails match (every end `>= e` is the same sequence in both results). `REQUIRE(e <= edit + config.max_size)`.

Register the binary in `tests/CMakeLists.txt` the same way as `test_image_pipeline`.
